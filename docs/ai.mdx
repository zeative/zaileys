Give your AI coding assistant accurate Zaileys knowledge, so it writes code that uses the real API instead of guessing.

## Pick the right tool

| You want to… | Use |
| --- | --- |
| Have Claude Code, Cursor, Codex, or OpenCode build, debug, or review Zaileys code | [The agent skill](#install-the-agent-skill) |

## Install the agent skill

The Zaileys agent skill is one skill, `zaileys`: instructions, reference files, project templates, and a project check that your assistant loads when you work on Zaileys code. It lives in the Zaileys repository, so you install it straight from `zeative/zaileys`.

<Tabs>
  <Tab title="Claude Code plugin">

    In Claude Code, add the Zaileys marketplace, then install the plugin:

    ```text
    /plugin marketplace add zeative/zaileys
    /plugin install zaileys-official@zeative
    ```

    Claude uses the skill on its own whenever you work on Zaileys code. To call it by name, type `/zaileys-official:zaileys`. To get new versions later, run this in your terminal:

    ```bash
    claude plugin marketplace update zeative
    claude plugin update zaileys-official@zeative
    ```

  </Tab>
  <Tab title="npx skills">

    The [`skills` CLI](https://github.com/vercel-labs/skills) installs the same skill into Claude Code, Codex, Cursor, OpenCode, and many other agents:

    ```bash
    npx skills add zeative/zaileys
    ```

    That installs into the current project, so everyone on the project gets it. To install for every project on your machine instead, add `-g`:

    ```bash
    npx skills add zeative/zaileys -g
    ```

    To update, run the same command again.

  </Tab>
</Tabs>

Both methods install the same skill. Use the plugin if you only use Claude Code. Use `npx skills` for any other agent, or when a whole team should share the skill through the project.

## What the skill does

You don't pick a mode. Ask for what you need, and the skill opens only the files that job needs:

| You ask for… | What the assistant does |
| --- | --- |
| A new bot | Picks the provider, login, and storage from your request, starts from a small runnable template, type-checks it, and ends with the exact steps only you can do — scanning the QR code, or filling in Meta credentials and the webhook URL. |
| A feature in an existing bot | Reads your project first and follows its structure. It checks the feature exists on your provider, and looks up the real API in your installed Zaileys before it writes. |
| A fix | Classifies the error, code, or symptom — `SEND_FAILED`, `401 invalid signature`, Meta code `131047`, a QR on every restart — finds the cause in your code, and fixes that instead of adding retries. |
| A review | Ranks real problems by what they break in production — ban risk, lost sessions, crashes, webhook security, the 24-hour window — with the file, line, and fix. |
| An upgrade or a deploy | Reads the changes between your version and the target, fixes what breaks, and sets up the server: session volume, memory and ffmpeg limits, one process per session. |

The skill ships these files:

| File | Covers |
| --- | --- |
| `SKILL.md` | The facts that prevent most mistakes, and which file to open for each job |
| `workflows/` | Step-by-step checklists for a new bot, a feature, debugging, reviews, and upgrades or deploys |
| `references/` | Providers, sending, receiving, commands and plugins, groups and channels, the Cloud API, storage and sessions, every error code, production, and version history |
| `assets/templates/` | Minimal runnable projects for WhatsApp Web and the Cloud API |
| `scripts/doctor.mjs` | A read-only check of your project |

### Check a project with the doctor

The doctor finds problems that compile fine but fail when the bot runs: a Cloud API client without `appSecret`, a JSON-parsed webhook body, an invalid `sessionId`, sends to `msg.chatId`, a disabled ban guard, a missing database driver, an ffmpeg without WebP support, or a Docker setup that loses the session on every rebuild. Your assistant runs it for you, and you can run it yourself from the skill's folder:

```bash
node scripts/doctor.mjs /path/to/your/bot            # human-readable
node scripts/doctor.mjs /path/to/your/bot --json     # for tools
node scripts/doctor.mjs /path/to/your/bot --online   # also compares with the latest release
```

It only reads files. It connects to the network only with `--online`, to look up the latest version on npm.

```text
zaileys doctor — /home/me/order-bot
zaileys 4.15.1 · Node.js v22.22.3

✗ cloud-app-secret: Cloud API client without cloud.appSecret: the webhook answers 401 to every delivery (src/server.ts:5)
    fix: set cloud.appSecret from the Meta app settings (e.g. process.env.WA_APP_SECRET)

12 ok, 0 warning(s), 1 error(s), 4 skipped
```

## Upgrade from the four skills

Earlier releases shipped four skills: `zaileys-assist`, `zaileys-scaffold`, `zaileys-debug`, and `zaileys-review`. The single `zaileys` skill replaces all of them.

<Tabs>
  <Tab title="Claude Code plugin">

    Update the marketplace and the plugin. The old skills are removed and the new one is installed in their place:

    ```bash
    claude plugin marketplace update zeative
    claude plugin update zaileys-official@zeative
    ```

    Then restart Claude Code. Call the skill as `/zaileys-official:zaileys` instead of `/zaileys-official:zaileys-assist`.

  </Tab>
  <Tab title="npx skills">

    `npx skills` keeps skills it installed before, so remove the four old ones first. Otherwise they compete with the new skill:

    ```bash
    npx skills remove zaileys-assist zaileys-scaffold zaileys-debug zaileys-review -y
    npx skills add zeative/zaileys
    ```

    If you installed them globally, add `-g` to both commands.

  </Tab>
</Tabs>

## Give a model the whole docs

Two plain-text files are generated from these docs automatically, so they always match the published pages:

- **`/llms.txt`** — a list of every page, with its title, link, and description. Good for a model that should find the right page on its own.
- **`/llms-full.txt`** — the full text of every page in one file. Attach it, or paste its link, when you want the model to know all of Zaileys.

Both sit at the root of this site, next to the pages. To get a single page as Markdown, add `.md` to its URL — for example, `/quickstart.md`.

## Send a page to an AI

Every page has a menu at the top, next to the title. From it you can:

| Option | What it does |
| --- | --- |
| Copy page | Copies the page as Markdown, ready to paste into any chat. |
| View as Markdown | Opens the page's Markdown source. |
| ChatGPT, Claude, Perplexity | Starts a new chat in that app, with the page as context. |
| Cursor, VS Code | Connects your editor to the docs' search server (an MCP server), so its assistant can look things up in these docs while it writes code. |

## Write prompts that work

A few habits make AI answers about Zaileys far more accurate:

- **Name the provider.** Say "Unofficial (WhatsApp Web)" or "Official (Cloud API)". Many features exist on only one ([feature matrix](/feature-matrix)).
- **Paste the whole error**, including its `code`, and the code that caused it.
- **Ask for a complete file** and how to run it, not a fragment.
- **Give it the source of truth.** With the skill installed, it already has one. Otherwise, attach `/llms-full.txt` or the page you're working from.

Prompts you can adapt:

```text Build a feature
Using Zaileys on the Unofficial provider (WhatsApp Web), write bot.ts that answers
/price <item> with the price from prices.json, and replies with a list of all items
when no item is given. Use client.command() and ctx.reply(). Show how to run it with npx tsx.
```

```text Fix an error
My Zaileys bot fails with ZaileysBuilderError, code MEDIA_LOAD_FAILED, when it sends
./menu.jpg. Here is the handler and the full error: <paste both>. What's wrong?
```

```text Review before shipping
Review this Zaileys bot before I deploy it to our main store number: ban risk,
lost sessions, and missing error handling. List findings with file and line.
```

```text Migrate providers
I'm moving this Zaileys bot from WhatsApp Web to the Cloud API. List every call that
would throw UNSUPPORTED_ON_CLOUD or NOT_IMPLEMENTED, and suggest a replacement for each.
```

<Tip>
  AI assistants still make mistakes. If a method or option looks unfamiliar, look it up in the [API reference](/reference/client) — every one is listed there.
</Tip>

## Common questions

<AccordionGroup>
  <Accordion title="Does the skill send my code anywhere?">
    No. It's a folder of Markdown files, templates, and one script installed on your machine. Your assistant reads them the same way it reads your code, and the doctor script only reads your project — it goes online only when you pass `--online`.
  </Accordion>
  <Accordion title="Which Zaileys version does the skill describe?">
    The v4 line. It also tells your assistant to check the Zaileys version installed in your project and read its type definitions, so answers match the version you actually run. Version-specific changes are collected in one reference file used for upgrades.
  </Accordion>
  <Accordion title="I still see zaileys-assist after updating">
    With the plugin, run `claude plugin marketplace update zeative` and then `claude plugin update zaileys-official@zeative`, and restart Claude Code. With `npx skills`, remove the old skills as shown in [Upgrade from the four skills](#upgrade-from-the-four-skills).
  </Accordion>
  <Accordion title="Which agents can use the skill?">
    Claude Code, through the plugin or `npx skills`. Codex, Cursor, OpenCode, and the other agents the `skills` CLI supports, through `npx skills`.
  </Accordion>
  <Accordion title="My assistant uses methods that don't exist">
    It's guessing from older or unrelated examples. Install the skill, or attach `/llms-full.txt`, and ask again. Naming the provider in your prompt also helps.
  </Accordion>
</AccordionGroup>
