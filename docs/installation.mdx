Add Zaileys to your project, then install only the extras your storage or media setup needs.

## Install the package

<CodeGroup>

```bash npm
npm install zaileys
```

```bash pnpm
pnpm add zaileys
```

```bash yarn
yarn add zaileys
```

```bash bun
bun add zaileys
```

</CodeGroup>

That's everything a working bot needs. Sessions are saved to files by default, and media conversion tools come bundled, so nothing else is required to get started.

## Check your Node.js version

Zaileys needs **Node.js 20 or newer**. Check yours with `node --version`.

Bun, Deno, and Termux (Android) work too, each with a few caveats — see [Runtimes](/data/runtimes).

## Import Zaileys

The package ships an ES module build and a CommonJS build, each with type declarations, so use whichever your project already uses:

<CodeGroup>

```ts ESM or TypeScript
import { Client } from 'zaileys'

const client = new Client()
```

```js CommonJS
const { Client } = require('zaileys')

const client = new Client()
```

</CodeGroup>

Your project is ESM when its `package.json` has `"type": "module"` or the file ends in `.mjs`. Otherwise it's CommonJS, and you use `require`.

<Accordion title="Setting up TypeScript">

  The types are included, so there's no `@types/zaileys` to install. A `tsconfig.json` like this works well:

  ```json tsconfig.json
  {
    "compilerOptions": {
      "target": "ES2022",
      "module": "NodeNext",
      "moduleResolution": "NodeNext",
      "strict": true,
      "skipLibCheck": true
    }
  }
  ```

  `skipLibCheck` matters: without it, `tsc` reports errors inside `node_modules` (in packages such as `ws` and `thread-stream`) that aren't in your code. To run a `.ts` file during development without a build step, use `npx tsx bot.ts`.

</Accordion>

## Add a storage driver (optional)

Zaileys saves the WhatsApp login and message history through storage adapters. The file and in-memory adapters need no extra packages. The others need a database driver, which you install yourself:

| Install | To use | Adapter classes |
| --- | --- | --- |
| Nothing | Files (the default for logins) or memory | `FileAuthStore`, `MemoryAuthStore`, `MemoryMessageStore` |
| `better-sqlite3@11` | SQLite | `SqliteAuthStore`, `SqliteMessageStore` |
| `pg` | PostgreSQL | `PostgresAuthStore`, `PostgresMessageStore` |
| `redis@4` | Redis (the official `redis` client, not `ioredis`) | `RedisAuthStore`, `RedisMessageStore` |
| `convex` | Convex | `ConvexAuthStore`, `ConvexMessageStore` |

Keep the version tags: Zaileys supports `better-sqlite3` 11 and `redis` 4, and a plain `npm install redis` would pull a newer major version outside that range.

For example, to keep the login in a SQLite file:

<CodeGroup>

```bash npm
npm install better-sqlite3@11
```

```bash pnpm
pnpm add better-sqlite3@11
```

```bash yarn
yarn add better-sqlite3@11
```

```bash bun
bun add better-sqlite3@11
```

</CodeGroup>

```ts bot.ts
import { Client, SqliteAuthStore } from 'zaileys'

const client = new Client({
  auth: new SqliteAuthStore({ database: './auth.db' }),
})
```

Zaileys loads a driver only when you use its adapter. If the driver isn't installed, the adapter fails with a `ZaileysStoreError` whose code is `STORE_NOT_AVAILABLE` — install the package from the table and restart.

In TypeScript, also add the type packages for SQLite and PostgreSQL: `npm install -D @types/better-sqlite3 @types/pg`. The `redis` and `convex` packages include their own types.

<Note>
  `better-sqlite3` compiles a native module when it installs. pnpm 10 and newer skip install scripts until you approve them, so run `pnpm approve-builds` if SQLite fails to load after a pnpm install.
</Note>

[Storage](/data/storage) shows how to set up each adapter.

## Speed up image processing with sharp (optional)

Zaileys resizes images and builds stickers with `jimp`, a JavaScript image library it already includes. If the faster native `sharp` package is installed, Zaileys uses that instead — no code changes needed.

<CodeGroup>

```bash npm
npm install sharp
```

```bash pnpm
pnpm add sharp
```

```bash yarn
yarn add sharp
```

```bash bun
bun add sharp
```

</CodeGroup>

`sharp` isn't a Zaileys dependency, but Baileys — the WhatsApp Web library Zaileys runs on — lists it as a required peer dependency, so npm tries to install it anyway. On platforms with no prebuilt `sharp` binary, such as Termux or some Alpine Linux images, that makes `npm install zaileys` fail while compiling `sharp`. Skip it with:

```bash
npm install zaileys --legacy-peer-deps
```

Images and stickers then use the bundled `jimp` path.

## ffmpeg comes bundled

Zaileys converts audio, video, and stickers with ffmpeg, and installs a matching ffmpeg and ffprobe binary for your platform. You don't need to install ffmpeg yourself.

For each binary, Zaileys uses the first of these that works:

1. **`FFMPEG_PATH` or `FFPROBE_PATH`**, when you set them.
2. **The bundled binary.** pnpm 10 and bun skip install scripts from dependencies by default, which leaves the bundled binary without permission to run — Zaileys grants that permission itself, so there's nothing to approve.
3. **`ffmpeg` or `ffprobe` on your `PATH`**, when your platform has no bundled binary, or Zaileys can't make it runnable — for example, when `node_modules` is read-only.

### Use your own ffmpeg

```bash
FFMPEG_PATH=/usr/bin/ffmpeg FFPROBE_PATH=/usr/bin/ffprobe node bot.js
```

Set both when you want a specific build, such as one with extra codecs. Zaileys uses the paths as they are, so a wrong path makes every conversion fail.

### Animated stickers

Animated stickers need ffmpeg's WebP encoder (`libwebp`), and not every build has it:

| Where the bot runs | Animated stickers |
| --- | --- |
| Linux (x86 or ARM), Windows, or an Intel Mac, with the bundled ffmpeg | Work |
| A Mac with Apple Silicon (M1 or newer), with the bundled ffmpeg | Fail — this build has no WebP encoder |
| Your own ffmpeg with the WebP encoder, through `FFMPEG_PATH` | Work in Zaileys 4.15.1 and newer |

On an Apple Silicon Mac, use your own ffmpeg. Homebrew's `ffmpeg-full` includes the WebP encoder; the plain `ffmpeg` formula doesn't:

```bash
brew install ffmpeg-full
FFMPEG_PATH="$(brew --prefix ffmpeg-full)/bin/ffmpeg" FFPROBE_PATH="$(brew --prefix ffmpeg-full)/bin/ffprobe" node bot.js
```

A failed conversion throws `MEDIA_LOAD_FAILED` with `sticker() conversion failed: …`. Stickers from photos don't use ffmpeg, so they work everywhere. On Zaileys 4.15.0, your own ffmpeg failed too when it was a newer release such as ffmpeg 9 (`FFmpeg exited with code 8`) — upgrade to 4.15.1.

## Check that it works

This script loads Zaileys without connecting to WhatsApp:

```ts check.ts
import { Client } from 'zaileys'

const client = new Client({ autoConnect: false })

console.log(`Zaileys loaded. Provider: ${client.provider}, state: ${client.state}`)
```

Run `npx tsx check.ts`. It prints:

```text
Zaileys loaded. Provider: baileys, state: idle
```

`autoConnect: false` stops the client from connecting on its own, so nothing asks you to scan a QR code. Remove it when you're ready to go online.

## Common questions

<AccordionGroup>
  <Accordion title="Do I need to install ffmpeg?">
    No. Zaileys installs its own ffmpeg binary, including on pnpm 10 and bun. It only uses a system ffmpeg when you set `FFMPEG_PATH`, or when the bundled binary is missing or can't run. [How Zaileys picks ffmpeg](#ffmpeg-comes-bundled)
  </Accordion>
  <Accordion title="npm install fails while building sharp">
    Your platform has no prebuilt `sharp` binary. Install with `npm install zaileys --legacy-peer-deps` — Zaileys then processes images with the bundled `jimp` library.
  </Accordion>
  <Accordion title="I get STORE_NOT_AVAILABLE when the bot starts">
    You're using a storage adapter whose driver isn't installed — for example `SqliteAuthStore` without `better-sqlite3`. Install the package listed in [Add a storage driver](#add-a-storage-driver-optional).
  </Accordion>
  <Accordion title="tsc shows errors inside node_modules">
    Those come from type declarations in Zaileys' dependencies, not from your code. Set `"skipLibCheck": true` in your `tsconfig.json`.
  </Accordion>
</AccordionGroup>
