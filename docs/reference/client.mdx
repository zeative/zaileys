## Create and connect

How the client moves between states is explained in [The client](/concepts/client#the-connection-lifecycle).

### `new Client()`

```ts Signature
import type { Client, ClientOptions } from 'zaileys'

interface ClientConstructor {
  new (options?: ClientOptions): Client
}
```

Creates a client. Unless `autoConnect` is `false`, it starts connecting straight away.

<ProviderSupport web={true} cloud={true} />

<ParamField body="options" type="ClientOptions" default="{}">
  Every field is optional — see [ClientOptions](/reference/client-options).
</ParamField>

**Throws:** with `provider: 'cloud'`, `ZaileysCloudError` with code `CONFIG` — `provider 'cloud' requires cloud.accessToken` or `provider 'cloud' requires cloud.phoneNumberId`. A failed auto-connect doesn't throw: it's emitted as an `error` event, and only if you listen for `error`.

```ts
import { Client } from 'zaileys'

const client = new Client({ sessionId: 'support-bot' })
client.on('error', ({ error }) => console.error('Could not connect:', error.message))
```

### `connect()`

```ts Signature
interface Client {
  connect(): Promise<void>
}
```

Opens the connection. You only need it with `autoConnect: false` or after `disconnect()`.

<ProviderSupport web={true} cloud={true} note="On the Cloud API, it checks your access token." />

<ResponseField name="returns" type="Promise<void>">
  On WhatsApp Web, resolves once the connection is open — after the QR code or pairing code is used, or straight away with a saved login. On the Cloud API, resolves once the token check passes and `connect` fires. If a connection is already in progress or open, it resolves immediately without waiting; listen for `connect` in that case.
</ResponseField>

**Rejects with:**

- `Error` — `phoneNumber is required when authType is "pairing"`.
- `Error` — `disconnected before connect resolved`, when `disconnect()` runs first (including after the [auth guard](/reference/client-options#authguardoptions) gives up).
- `Error` — `connection closed (logged-out)` (or another reason), when the connection closes and won't reconnect.
- Cloud API: `ZaileysCloudError` `AUTH` — `cloud auth rejected (401) — check accessToken/phoneNumberId`; `REQUEST_FAILED` — `cloud health-check request failed` or `cloud health-check failed (500)`.

```ts
import { Client } from 'zaileys'

const client = new Client({ autoConnect: false })
client.on('qr', ({ qrString }) => console.log('Show this QR in your app:', qrString))

await client.connect()
```

### `disconnect()`

```ts Signature
interface Client {
  disconnect(): Promise<void>
}
```

Closes the connection and keeps the login, so the next `connect()` doesn't need a new QR code. On WhatsApp Web, it also stops commands, plugins, auto-delete, and scheduled-message timers, and closes the auth and message stores. It emits `disconnect` with `willReconnect: false`, and does nothing if the client isn't connected.

<ProviderSupport web={true} cloud={true} />

<ResponseField name="returns" type="Promise<void>">
  Resolves once everything is closed. Errors while closing are logged as warnings, not thrown.
</ResponseField>

```ts
process.on('SIGINT', async () => {
  await client.disconnect()
  process.exit(0)
})
```

### `logout()`

```ts Signature
interface Client {
  logout(): Promise<void>
}
```

Unlinks the bot from the phone, deletes the saved login, and disconnects. The next `connect()` shows a new QR code. It emits `disconnect` with reason `logged-out`. On the Cloud API there's no linked device — it just disconnects.

<ProviderSupport web={true} cloud={true} />

<ResponseField name="returns" type="Promise<void>">
  Resolves when done. Failures along the way are logged as warnings, not thrown.
</ResponseField>

```ts
await client.logout()
```

## Events

Every event name and payload is in the [Events reference](/reference/events).

### `on()`

```ts Signature
import type { ClientEventMap } from 'zaileys'

interface Client {
  on<E extends keyof ClientEventMap>(event: E, handler: (payload: ClientEventMap[E]) => void): () => void
}
```

Runs `handler` every time `event` fires. There's no `once()` — call the returned function to stop listening.

<ProviderSupport web={true} cloud={true} />

<ParamField body="event" type="keyof ClientEventMap" required>
  An event name, such as `'text'`, `'connect'`, or `'button-click'`.
</ParamField>
<ParamField body="handler" type="(payload) => void" required>
  Receives the event's payload, typed for that event.
</ParamField>
<ResponseField name="returns" type="() => void">
  Removes this handler. Calling it twice is safe.
</ResponseField>

<Warning>
  An error in a handler never becomes an `error` event. A handler that throws synchronously is caught and logged as `listener threw` — invisible unless you set a logger or `ZAILEYS_DEBUG`. A rejected `async` handler isn't caught at all, so Node reports an unhandled rejection. Wrap the body of async handlers in `try`/`catch`.
</Warning>

```ts
const stop = client.on('text', async (msg) => {
  await msg.reply(`You said: ${msg.text}`)
})

setTimeout(stop, 60_000)
```

### `off()`

```ts Signature
import type { ClientEventMap } from 'zaileys'

interface Client {
  off<E extends keyof ClientEventMap>(event: E, handler: (payload: ClientEventMap[E]) => void): void
}
```

Removes a handler. Pass the same function you gave to `on()`.

<ProviderSupport web={true} cloud={true} />

```ts
import type { MessageContext } from 'zaileys'

const logText = (msg: MessageContext) => console.log(msg.senderId, msg.text)

client.on('text', logText)
client.off('text', logText)
```

### `removeAllListeners()`

```ts Signature
import type { ClientEventMap } from 'zaileys'

interface Client {
  removeAllListeners(event?: keyof ClientEventMap): void
}
```

Removes every handler for one event, or for all events when you pass nothing.

<ProviderSupport web={true} cloud={true} />

<Warning>
  Zaileys listens to some events itself: `message` drives commands and disappearing-timer inheritance, and `call-incoming` drives `autoRejectCall`. Removing all listeners for those events — or for everything — switches those features off. Prefer the function `on()` returns.
</Warning>

```ts
client.removeAllListeners('qr')
```


How many handlers are attached to an event, including Zaileys' own.

<ProviderSupport web={true} cloud={true} />

## Send and change messages

### `send()`

```ts Signature
import type { MessageBuilder } from 'zaileys'

interface Client {
  send(to: string): MessageBuilder<'init'>
}
```

Starts a message. Add one content method, then `await` to send — every method is in the [Send builder reference](/reference/send-builder).

<ProviderSupport web={true} cloud={true} />

<ParamField body="to" type="string" required>
  A <Term id="jid" /> or a bare phone number. On WhatsApp Web, a bare number is looked up when you await; on the Cloud API it's passed to Meta as it is.
</ParamField>
<ResponseField name="returns" type="MessageBuilder<'init'>">
  A builder. Awaiting it after a content method resolves to the sent message's `WAMessageKey`.
</ResponseField>

**Throws:** `ZaileysBuilderError` `INVALID_OPTIONS` — `client not connected`, straight from `send()`, before you add content. On the Cloud API this lasts until the `connect()` token check has finished.

```ts
const key = await client.send('6281234567890@s.whatsapp.net').text('Your order #1042 has shipped.')
```

### `edit()`

```ts Signature
import type { EditBuilder, WAMessageKey } from 'zaileys'

interface Client {
  edit(key: WAMessageKey): EditBuilder
}
```

Starts an edit of a message the bot sent. Call one of the builder's methods, then `await`:

| Method | Replaces the message with |
| --- | --- |
| `.text(content: string)` | New text |
| `.image(src: MediaSource, opts?: ImageOptions)` | A new photo |
| `.video(src: MediaSource, opts?: VideoOptions)` | A new video |

<ProviderSupport web={true} cloud={false} />

<ParamField body="key" type="WAMessageKey" required>
  The key of the message to edit, as returned by `send()`.
</ParamField>
<ResponseField name="returns" type="EditBuilder">
  Awaiting it resolves to the edit's `WAMessageKey`.
</ResponseField>

**Throws:** `ZaileysProviderError` `UNSUPPORTED_ON_CLOUD` on the Cloud API; `ZaileysBuilderError` `INVALID_OPTIONS` — `client not connected`. When you await: `INVALID_OPTIONS` — `message key is missing remoteJid`; `EMPTY_CONTENT` — `edit() requires a content method before await`; `SEND_FAILED` — `socket sendMessage rejected` or `socket returned no message key`; plus the media errors from [`image()`](/reference/send-builder#image) and [`video()`](/reference/send-builder#video).

```ts
const key = await client.send(jid).text('Order status: packing')
await client.edit(key).text('Order status: shipped')
```

Guide: [Edit a message](/messaging/edit-delete-react#edit-a-message).

## Modules

Groups, chats, contacts, and the rest live on module properties such as `client.group`. They share three rules:

- **WhatsApp Web only.** Reading one of these properties on the Cloud API throws `ZaileysProviderError` with code `UNSUPPORTED_ON_CLOUD` — for example `group is not supported by the official WhatsApp Cloud API — it only exists on the web (baileys) provider`.
- **Connected first.** Calling a module method before the client is connected throws `ZaileysDomainError` with code `NOT_CONNECTED` (`client not connected`). `presence` throws `ZaileysAutomationError` with the same code and message.
- **Paced for you.** Group, community, and channel operations are spaced out by [`operationGuard`](/reference/client-options#operationguardoptions), and repeated presence updates are dropped by the [`presence` throttle](/reference/client-options#presencethrottleoptions).

Every module method, its parameters, and its errors are documented on the linked guide page.

### `group`

```ts Signature
import type { GroupModule } from 'zaileys'

interface Client {
  readonly group: GroupModule
}
```

Create and manage groups, their members, settings, and invites.

<ProviderSupport web={true} cloud={false} />

**Methods:** `create`, `metadata`, `list`, `addMember`, `removeMember`, `promote`, `demote`, `updateSubject`, `updateDescription`, `setting`, `toggleEphemeral`, `memberAddMode`, `joinApproval`, `joinRequests`, `approveJoin`, `rejectJoin`, `tagMember`, `inviteCode`, `revokeInvite`, `acceptInvite`, `inviteInfo`, `leave`.

### `webhook()`

```ts Signature
interface Client {
  webhook(): (req: Request) => Promise<Response>
}
```

Returns the handler Meta calls with every message and status update. It takes a standard `Request` and returns a `Response`, so it plugs into Next.js, Hono, Bun, and anything else built on the Fetch API. Deliveries are processed even before `connect()` finishes.

<ProviderSupport web={false} cloud={true} />

<ResponseField name="returns" type="(req: Request) => Promise<Response>">
  How it answers:

  | Request | Response |
  | --- | --- |
  | `GET` with `hub.mode=subscribe` and the right `hub.verify_token` | `200` with `hub.challenge` |
  | Any other `GET` | `403` |
  | `POST` with a bad `X-Hub-Signature-256` (when `appSecret` is set) | `401` |
  | `POST` whose body isn't JSON | `400` |
  | Any other `POST` | `200` — always, even if your handlers fail, so Meta doesn't retry |
  | Other methods | `405` |
</ResponseField>

**Throws:** `ZaileysCloudError` `CONFIG` — `webhook() is only available on the cloud provider`.

```ts app/api/whatsapp/route.ts
const webhook = client.webhook()
```

## Commands

Commands need a [`commandPrefix`](/reference/client-options#incoming-messages-and-commands) and run on WhatsApp Web only. You can register them before connecting; they start working once the client connects. Full details are in the [Commands reference](/reference/commands).

### `command()`

```ts Signature
import type { CommandHandler, CommandSpec } from 'zaileys'

interface Client {
  command(spec: string | CommandSpec, handler: CommandHandler): this
}
```

Registers a command. Returns the client, so calls chain.

<ProviderSupport web={true} cloud={false} />

<ParamField body="spec" type="string | CommandSpec" required>
  The name, with aliases after `|` — for example `'help|h'` — and spaces for subcommands, such as `'order cancel'`. Or an object with `name`, `aliases`, `description`, `usage`, `category`, `hidden`, `metadata`, and the guards `group`, `private`, `admin`, and `cooldown` (seconds).
</ParamField>
<ParamField body="handler" type="(ctx: CommandContext) => Promise<void> | void" required>
  Runs when the command matches. `ctx` is the message plus `command`, `args`, `flags`, `reply()`, and more.
</ParamField>

**Throws:** `ZaileysCommandError` `DUPLICATE_COMMAND` — `command "price" is already registered`; `INVALID_COMMAND_NAME` — `command spec must not be empty`.

```ts
client.command({ name: 'price', aliases: ['harga'], description: "Today's prices", cooldown: 10 }, async (ctx) => {
  await ctx.reply('Rice 5 kg: Rp75.000\nCooking oil 2 L: Rp38.000')
})
```

## Automation

### `broadcast()`

```ts Signature
import type { BroadcastOptions, BroadcastResult, MessageBuilder } from 'zaileys'

interface Client {
  broadcast(
    jids: string[],
    build: (b: MessageBuilder<'init'>) => MessageBuilder<'content-set'>,
    options?: BroadcastOptions,
  ): Promise<BroadcastResult>
}
```

Sends the same message to many chats, one at a time and rate-limited.

<ProviderSupport web={true} cloud={false} />

<ParamField body="jids" type="string[]" required>
  The recipients.
</ParamField>
<ParamField body="build" type="(b: MessageBuilder<'init'>) => MessageBuilder<'content-set'>" required>
  Adds content to a builder already addressed to one recipient. Called once per recipient.
</ParamField>
<ParamField body="options.rateLimitPerSec" type="number" default="5">
  The most messages sent per second. Must be greater than `0`.
</ParamField>
<ParamField body="options.retry" type="{ maxRetries: number; backoffMs: (attempt: number) => number }">
  Retry each failed recipient up to `maxRetries` times, waiting `backoffMs(attempt)` between tries.
</ParamField>
<ParamField body="options.onProgress" type="(done: number, total: number, jid: string, ok: boolean) => void">
  Called after each recipient.
</ParamField>
<ResponseField name="returns" type="Promise<BroadcastResult>">
  `{ sent: string[], failed: { jid, error }[] }`. A failed recipient never rejects the whole broadcast.
</ResponseField>

**Throws:** `ZaileysBuilderError` `INVALID_OPTIONS` — `client not connected`, which is always the case on the Cloud API. `ZaileysAutomationError` `RATE_LIMIT_INVALID` — `perSec must be greater than zero`.

```ts
const result = await client.broadcast(
  ['6281234567890@s.whatsapp.net', '6289876543210@s.whatsapp.net'],
  (b) => b.text('We open at 10am tomorrow for the holiday.'),
  { rateLimitPerSec: 1, onProgress: (done, total) => console.log(`${done}/${total}`) },
)
console.log(`Sent ${result.sent.length}, failed ${result.failed.length}`)
```

Guide: [Send one message to many chats](/bots/broadcast-and-schedule#send-one-message-to-many-chats).

### `scheduleAt()`

```ts Signature
import type { MessageBuilder, ScheduleHandle } from 'zaileys'

interface Client {
  scheduleAt(
    date: Date,
    build: (b: MessageBuilder<'init'>) => MessageBuilder<'content-set'>,
  ): Promise<ScheduleHandle>
}
```

Sends a message at a set time. The message is prepared right away — files included — and saved to the store when the adapter supports scheduled messages, so it survives a restart. Due messages go out at most [`scheduleRateLimitPerSec`](/reference/client-options#guards-and-rate-limits) per second.

<ProviderSupport web={true} cloud={false} note="Scheduled sends fail on the Cloud API." />

<ParamField body="date" type="Date" required>
  When to send. A time in the past sends straight away.
</ParamField>
<ParamField body="build" type="(b: MessageBuilder<'init'>) => MessageBuilder<'content-set'>" required>
  Builds the message. The builder has no recipient, so start with [`.to(jid)`](/reference/send-builder#to).
</ParamField>
<ResponseField name="returns" type="Promise<ScheduleHandle>">
  `{ id, cancel() }`. `cancel()` stops the send and removes the saved job.
</ResponseField>

**Rejects with:** `ZaileysAutomationError` `SCHEDULE_INVALID` — `scheduleAt requires a valid Date`, `scheduled builder produced no content`, `scheduled builder evaluation failed` (the builder's error is on `cause`), `scheduling multi-part messages (e.g. album) is not supported; schedule a single message`, or `scheduling interactive/relayed content is not supported; schedule a text or media message`.

If sending fails when the time comes — for example because the client is offline — the job is kept and tried again the next time the client connects.

```ts
const handle = await client.scheduleAt(new Date('2026-12-24T09:00:00+07:00'), (b) =>
  b.to('6281234567890@s.whatsapp.net').text('Merry Christmas from Toko Budi!'),
)
console.log('Scheduled job', handle.id)
```

Guide: [Send a message later](/bots/broadcast-and-schedule#send-a-message-later).

## Common questions

<AccordionGroup>
  <Accordion title="Is there a once() method?">
    No. `on()` returns a function that removes the handler — call it inside the handler to run it once.
  </Accordion>
  <Accordion title="Why does connect() resolve before the bot is connected?">
    A connection was already in progress — usually from `autoConnect` — so `connect()` returned straight away. Listen for the `connect` event, or create the client with `autoConnect: false` and call `connect()` yourself.
  </Accordion>
  <Accordion title="Why don't I see errors from my handlers?">
    A synchronous throw is caught and logged through the logger, which is silent by default. Set `ZAILEYS_DEBUG=1` to see it, and wrap async handlers in `try`/`catch` — their rejections aren't caught by Zaileys.
  </Accordion>
  <Accordion title="Which members can I use on the Cloud API?">
    Everything marked **Both** or **Cloud API** in the [Quick reference](#quick-reference). The rest throw `UNSUPPORTED_ON_CLOUD` or `client not connected`, or return an empty result.
  </Accordion>
</AccordionGroup>
